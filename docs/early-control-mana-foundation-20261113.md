# Uninterrupted control and distinguishable replacement choices

Merieke Ri Berit and Orcish Squatters require an uninterrupted source-control
interval (CR 611.2b). Losing and regaining control before resolution prevents the
old ability's effect from beginning. A callback that checks only the current
controller cannot answer that historical question. A condition that becomes true
during resolution itself can begin a new interval.

The native foundation appends `Duration::WhileSourceControlled` and extends the
existing source-interval reader. It uses the stack item's existing creation mark
and the resolving frame's existing history boundary. It adds no parallel state,
new counters, numeric widening, or generic reconstruction of arbitrary predicates.
Tap/untap events do not end a control-only duration. Control changes, battlefield
departure, and phasing use the existing duration authority. The shared gain-control
recipe and seven existing printed consumers migrate to the explicit duration;
the legacy current-state predicate remains available for custom conjunctions.

A forced core regression fails with the old callback and passes with the native
duration. The unbroken interval, tapping independence, permanent expiry, and a
condition restored during resolution are retained controls. All existing source-tap
and nested mana-ability interval tests remain part of validation. Three interleaved
128-game benchmark pairs complete without unfinished games; allocation remains
29.34 KB per decision. Median engine-answer timing is 58.36 us before and 54.43 us
after on this busy shared host; these measurements do not establish a speedup.

Naked Singularity and Reality Twist have a further unresolved single-effect
grouping error, reported after this batch as [Oracle Grammar #19](https://github.com/vishvananda/oracle-grammar/issues/19).
The independent reviewer correctly rejected the sequential replacements: choosing
an arm can yield the other arm's color. This batch fixes only the labels, and
its unchanged-outcome controls do not prove the complete mana-replacement rule.
Both cards remain blocked. Their generated replacement arms previously reused
the same complete sentence as
the choice label. A dual land therefore presented indistinguishable choices. The
backend now identifies each arm's single basic land type and fixed mana color,
and uses its verbatim printed clause (for example, `Plains produce {R}`). The
printed text labels the choice; it does not determine the rule's behavior. Other
replacement shapes keep the full printed label.

Polar Kraken uses the existing generic cumulative-upkeep sacrifice payment. Its
shared question said “creature” even when the actual selection required lands.
The question now says “permanent”; its filter still determines the eligible
sacrifices. This is presentation only.

The control and upkeep-caption fixes require no Source/IR/schema changes. The
compound-mana reference grouping needs the separate #19 investigation; distinct
labels alone do not complete those two cards.
The conclusions on rejected MTGish reports #120/#125 remain in
[the contract review](rejected-upstream-contracts-20261113.md).

The native runtime harness in
`rust_syntax/normalize/tests/fixtures/early_control_mana_native/` uses complete
before/after generated modules and test-only card tables. Copy its Rust harness to
an isolated native checkout's `crates/cantrip-script/tests/`, and its scenarios to
`tests/fixtures/early-control-mana/` there. Generate modules for Orcish Squatters,
Naked Singularity and Reality Twist from the frozen `early_control_mana_20261113`
Source and Oracle fixtures. The harness checks the retained interruption scenario,
its ordinary controls, actual dual-land prompt labels, and unchanged mana results.
Both runs use identical generated printed-characteristics wrappers because the native Oracle
crate exports constants only for registered production content. No effect body is
rewritten. The old modules fail exactly three counterexamples (control interruption
and both choice labels), with four controls passing; all seven pass after the fix.
The separate core regression establishes the old engine behavior. Do not register
these provisional definitions in the production foundation.

Tetravus remains separate: `may_pay_x` exposes a mana-X prompt for an arbitrary
counter-removal cost. `may_pay_counted` does not announce the variable source
counter count and is not a correct replacement. A fixed `remove_counters` cost
holds only `u8`; converting an arbitrary available count into it would truncate.
The native follow-up now gives the existing X interface a shared source-counter
bound and no counter-only mana window. After filesystem recovery, the full
foundation suite passes; see [the payment and display follow-up](early-counter-payments-20261113.md). Storage lands (for example
Bottomless Vault) are the second printed consumer of that same cost bound.
Triskelavus uses a fixed one-counter activation, not Tetravus's optional any-number
removal; it is not evidence for the latter interface. The focused core, retained card scenario, and full foundation suite pass.
