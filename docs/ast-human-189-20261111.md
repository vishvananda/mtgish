# Schema189: numeric predicates, countering and compact storage

This implements the [AST review](ast-ui-review-20261111.md). Numbers remain scalar;
numeric matching has its own type. Countering has one operation with typed
movement destinations. The common native nodes take substantially less space.
No engine numeric width is changed and no new engine feature is implemented.

## Semantic shapes

`NumberTest` has `Compare { comparison, value }`, `AllOf`, `AnyOf`, and
`AnyProperty { comparison, objects, property }`. `Expr::AnyOf` and
`Aggregation::AnyOf` are removed. An action amount or arithmetic operand cannot
accept a list of alternatives as though it were one number. Conditions compare
`left: Expr` against `test: NumberTest`; object property filters and nth-event
filters use the same predicate type. X restrictions also use predicates, including
activation `XIs` and instruction `LimitX`. Scalar aggregations remain Sum/Min/Max.

Alternatives retain existential comparison semantics: `x != 1 OR x != 2` does
not become `x NOT IN {1,2}`. Empty AnyOf is false; empty AllOf is true. AnyProperty
compares against current property values of the supplied objects; an empty set
matches nothing. Source comparison lowering routes alternatives to predicate
positions, including ordinary hand-count conditions, rather than manufacturing
a scalar or dropping a reading. Scalar-only bounds reject nonscalar alternatives.

`Counter { objects, destination, destination_when }` replaces Counter/CounterWith.
It accepts an ObjectSet (One handles a single reference) and MovementDestination,
including arrival state and placement terms. A destination filter selects the
special destination; a nonmatch is still countered to its owner's graveyard.
The counter must succeed before its movement destination applies. Existing stack
spell/ability handling and the common direct counter paths are retained. The
block editor offers one counter action with a stack selector and optional
conditional destination. The hidden invalid producer `DraftChangeZone` remains a
separate compatibility boundary; address-only Destination uses elsewhere remain.

Conditions and object filters now use AllOf/AnyOf; EventSpec uses AnyOf.
ObjectFilter::Any still means an unrestricted filter. Instruction::Times becomes
RepeatableWithLimit, with the same total-run cap and private result scope. It
remains distinct from Repeatable's exported receipts and from fixed-count Repeat.
Registration of delayed triggers remains in its original lexical position.

## Human authoring and blocks

Rust owns shared value roles, operator families, labels and semantic defaults;
`human::editor_metadata()` exports them to the editor. Current-or-last-known
property reads and the ordinary counter destination no longer have separately
hardcoded JavaScript defaults. The editor presents numeric tests in compact form
and supports typed alternatives in comparison holes. NumberTest outputs cannot
connect to scalar Expr amounts. Optional destination filters remain editable.
The AST dump continues omitting empty/default characteristics as before.

Names stay in the authoring document; canonical numeric IDs, event participants,
receipt groups, current-versus-captured reads, and cardinality distinctions stay
in execution IR. No browser workspace migration was added for this unused
prototype. Existing persisted IR/document migrations still support their declared
epochs, now including188, with strict fields and binding-origin transport.

## Native storage

| Type, 64-bit build | Before | After |
| --- | ---: | ---: |
| Operation | 1,736 B | 904 B |
| Instruction | 1,744 B | 912 B |
| Ability | 1,488 B | 1,040 B |
| Announcement | 480 B | 32 B |
| Expr / Condition / ObjectFilter | 96 / 384 / 168 B | unchanged |

Optional modal data is boxed only when present. Large trigger events and PlayWith
terms are also stored out of line. Common effects, comparisons and nonmodal
announcements gain no allocation. Serde/bincode preserve the payload structure
through Box; these layout optimizations add no wire-level wrapper or binding path.
Size-budget regressions protect the hot node sizes. Pipeline timing and peak
process memory are measured separately from these native layout sizes; see the
validation/performance receipt rather than inferring speed from size alone.

## Migration and verification

Frozen189 descriptors and signature define the new contract. The typed upgrade
moves predicate value subtrees and single-counter references explicitly, carries
IDs through their new paths, and retains prior epoch checks. Wrong-scope references
remain errors. A separate structural conversion of all 33,529 schema188 records
matches fresh native lowering exactly before the three separately reviewed counter
reference corrections. New whole-card controls exercise source lowering, scoped
migration, mapped origins, scalar rejection, comparisons and size budgets.
Historical captures retain their saved bytes; test-only compatibility adapters
account for the deliberate representation changes. Existing independent expected
programs are mechanically updated where they describe the current schema.

The three [shared-verb counter repairs](counter-kinds-reference-20261111.md) change
actual card semantics independently of this migration. No equality alias hides
those differences. Evidence and reproducible test/benchmark artifacts are under
`/mnt/vizier/ast-human-189-20261111`.

Validation: **1,532 Rust tests pass** across 179 targets including doc tests;
19 tests remain explicitly ignored. The four IR contract tests and four focused
predicate/layout/migration controls also pass. Full Go passes. All33,529 browser
roundtrips, independently walked binding ports and actual Rust/Wasm validations
pass. Thirteen editor suites and 26 real rendered card workspaces pass without
JavaScript errors. The strict Rust migration independently preserves every native
program and transports **116,136 old binding sites**, introducing none.

Three interleaved runs per binary at each worker count measured the same immutable
Source input, including lowering, validation and JSON export. At 32 workers,
median CPU is 62.44s before and 62.68s after (+0.4%); peak RSS falls from 274,904KiB
to 245,592KiB (−10.7%). Wall medians are2.42s and 2.48s, within noisy observed
ranges; no speedup is claimed. At 1 worker, median CPU falls from 70.58s to 62.31s,
while peak RSS rises from 128,924KiB to 133,600KiB (+3.6%). Do not infer total
process memory from enum sizes or claim every configuration uses less memory.
Both binaries include the same IndexMap feature symbols. Raw runs, binary/input
hashes, scope and limits are in the [proof receipt](ast-human-189-20261111.proof.json).
