# Battlefield permanent domains include typeless objects

The typed source selector `Permanents::IsPermanent` can range over battlefield permanents. Its Rust selector rule incorrectly added a disjunction of six card types. A permanent can lose every card type and remain on the battlefield, so that additional requirement excludes legal objects. An internal `PermanentDomain` predicate now preserves its provenance until binding. It emits `Any` when a target, zone query or ability context supplies the permanent domain independently.

The correction is restricted to the `Permanents` domain. `IsPermanent` in the card, spell, hand, graveyard and exile domains still requires a permanent card type. Literal card-type disjunctions also retain their predicates. No canonicalizer, comparison alias, schema or public type changes are involved. The English parser emits a valid typed permanent selector; this is a fork lowering defect, so it does not warrant another upstream English-parser report.

The worker's typeless-object witness uses March of the Machines and Neurok Transmuter: removing artifact status from an animated noncreature artifact stops March's animation from applying, leaving the same battlefield permanent with no card types. With a time counter transferred by Nesting Grounds, it remains a valid permanent target for the put-counter modes of Shivan Sand-Mage and Timebender. This is a manually reasoned rules witness, not a game execution claim. The worker's complete evidence is in `reference-audit/suspended-permanent-domain.json` and `mixed-counter-targets/reference-issue.json` under `~/oracle-grammar/reports/analysis`.

All 248 observed uses of this typed selector were reviewed by domain and caller scope. They occur in 225 source records and produce 259 filters after lowering duplicates some operands. The scoped correction changes 226 filters across 196 records. The complete before/after IR comparison proves that these records change exclusively by replacing this exact six-type filter with `Any`; every other operand and all other records remain identical. Parser output is unchanged.

Target and object-set operands retain their domain. Trigger-rule source matching retains its independent `triggering.permanent` guard, including look-back triggers; activation-rule matching retains its battlefield-definition check. Raw event adapters can discard an `ObjectSet` domain when producing an `ObjectFilter`. Their binding context conservatively retains the previous six-type filter. This withholds 33 filters in 32 records, of which 29 records remain entirely unchanged. Removing those guards without an independent domain would admit instant/sorcery cards outside the battlefield. Counter replacements, counter/targeting triggers, raw conditions and event history therefore need a separate domain-preservation review. The scoped fix makes no such widening.

This resolves the reported domain errors on Black Bolt, Inhuman King; Deputy of Detention; Fractured Realm; Mirrorform; Press the Enemy; Sink into Stupor; Shivan Sand-Mage; Timebender; Wanderwine Farewell; Eventide's Shadow; and the newer Etched Slith finding. Existing nonland, non-Aura, time-counter, controller, damage-source exclusion, count, suspended-card and effect operands remain intact. Solid Ground's raw counter-replacement case remains withheld. Independent findings on these cards remain separate. Timecrafting's existing-time-counter requirement is corrected in the subsequent [template fix](reference-timecrafting-20261106.md), separately from this lowering change.
