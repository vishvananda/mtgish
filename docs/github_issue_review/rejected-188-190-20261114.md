# MTGish #188 and #190: lowering contracts, not new AST forms

Reviewed the issue bodies and maintainer replies on 2026-11-14. The requested
issue pair is **188 and 190**, correcting the earlier mention of 198. No
upstream source was pulled and no Oracle snapshot was changed.

## #188 — resolution-time X

<https://github.com/i5jb/mtgish/issues/188>

The maintainer states that `PayManaAnyX` and
`Reflexive_PayManaAnyX_WhenYouDo` include choosing X as part of their semantics.
That confirms our adapter must implement the choice; it does not require the
source grammar to emit a separate announcement instruction.

The normalized AST already distinguishes a resolving `ManaWithX { x: None }`
payment from a spell/activation's `AnnouncedX`. The payment has a result ID,
and `BoundValue(result)` supplies the chosen number to the reflexive trigger.
`lower_reflexive.rs::reflexive_body` already captures that actual result ID
following commit `cdb9f330840697d24b2fa9eaa0c2f89a0dbe8b19`.

The user confirmed retaining that adapter fix. In particular, do not replace the payment result with
the enclosing announced X, a hardcoded result zero, or an extra source action.
Existing `reference_costs` regressions cover the three printed cards and a
payment after an earlier action, where the payment result is nonzero.

**Classification:** adapter lowering bug already fixed; no AST representation
or schema change, and no new oracle-grammar AST defect established.

## #190 — a nonnegative repetition count

<https://github.com/i5jb/mtgish/issues/190>

The maintainer defines `AdjustPTForEach(p, t, n)` as applying the adjustment
`max(0, n)` times. It is not unrestricted signed multiplication by `n`.
Thus the normalized form is:

```text
Pump {
    power: p * Maximum(0, n),
    toughness: t * Maximum(0, n),
}
```

The existing AST has `Pump`, `Multiply`, and `Maximum`, so it can express this
exactly. Signed `Multiply` must keep its ordinary meaning; globally clamping
negative arithmetic or PT adjustments would be incorrect.

Reverted the phrase-specific grammar workaround at
`grammars/english_grammar.json5` and the two affected source records in RON,
JSON and pretty RON. The parser now retains upstream's `Minus(count, 1)`.
`lower.rs::layer_changes` instead clamps at the general `AdjustPTForEach`
lowering boundary. Known cardinalities retain their already nonnegative form,
existing nonnegative maxima are not nested, and unknown signed expressions
receive `Maximum(0, n)`. Controls cover negative, zero and positive counts
with both positive and negative PT increments; `AdjustPTX` and ordinary signed
`AdjustPT` retain their signed arithmetic.

The independent grammar already explicitly clamps its
`continuous_beyond_first` count in `grammar/syntax/effects.ebnf`. No missing
AST form is demonstrated there either. If canonical expression shapes change
during the general adapter correction, coordinate that face-output update
with oracle-grammar; do not mutate its pinned reference or published bundles
locally.

**Classification:** general adapter lowering correction, implemented here;
existing AST is sufficient. No new AST variant, numeric widening, or Cantrip
engine feature is justified by this rejection.

No oracle-grammar AST bug was filed: neither rejection establishes one.
The grammar's existing Wurm clamp already expresses the same meaning, while
our adapter now also handles upstream's implicit repetition contract.

Validation uses the existing Oracle input: all 33,529 freshly parsed source
records exactly match the checked-in reverted export. The 182 reviewed audit
findings are unchanged by ID; only the grammar input fingerprints change.
No immutable reference, published bundle or schema descriptor was edited.
