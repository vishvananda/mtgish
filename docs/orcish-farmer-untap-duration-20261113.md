# Orcish Farmer: next untap deadline

Orcish Farmer changes a land until its controller's next untap step. The relevant controller is the player controlling that land when an actual untap step begins; the effect waits through skipped untap steps. A player captured when the ability resolves is insufficient if control changes. The [rules discussion specifically about this card](https://www.reddit.com/r/mtgrules/comments/1iowygz/orcish_farmer_its_controller_time_of_ability_or/) describes that distinction. The frozen corpus contains one controller-dependent `UntilPlayersNextUntapStep` record, Orcish Farmer.

Two isolated native scenarios in `rust_syntax/normalize/tests/fixtures` demonstrate the problem. `orcish-farmer-duration-follows-land-controller.cantrip` uses the test-only `proof_take_land.rs`; the snapshot-player output leaves the land a Swamp at its new controller's next untap step. `orcish-farmer-skipped-untap-control.cantrip` uses `proof_skip_untap.rs` and verifies that a skipped untap does not expire the effect. These proof-only cards are not engine or card-table additions.

The native `Duration::UntilNextStepOf { step: Step::Untap, player: Some(player) }` handles fixed-player deadlines and skipped steps but stores a player, not a reference whose controller is checked later. `DuringItsControllersNextUntapStep` follows current control but lasts through the step and is specialized to untap restrictions, rather than ending before untap actions.

A generic `Duration::AsLongAs` / `Lasting::holds` cannot reliably implement this deadline with current interfaces. The callback receives `ContinuousEffect`, whose `timestamp` is a layer timestamp, not a history serial or creation turn. The untap path checks whether the step is skipped in private `static_rules::skips_step` and deliberately does not emit an untap `StepBegan` event. `expire_step_deadlines` runs before untap actions, but invokes lasting-condition settlement only when a recognized fixed-player step deadline changes. A `holds` predicate therefore cannot distinguish a skipped step and is not guaranteed to be evaluated at the required instant; a history search also cannot uniquely anchor repeated effects from the same source.

Until a native duration or equivalent interface tracks the affected object, expires immediately before the first actual untap step of its then-current controller, waits through skipped steps, and handles independently created effects, production generation reports an explicit gap for controller-dependent next-untap deadlines. Fixed-player next-untap deadlines continue to use `UntilNextStepOf`.
