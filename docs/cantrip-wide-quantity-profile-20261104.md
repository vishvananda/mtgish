# Wide Cantrip quantity profile

The generator profile targets native foundation7c77eca06e7c3d7329b026a86d83d1eb6ca75101.
Its API fingerprint is0f5cfaa6bdad8ceb98f16068d8d459f3de415d4dc2df288ee673c9978024b0f4.
Damage, counter placement, life-effect and poison-effect quantities follow the checked native
signatures. Physical storage, number-choice domains and smaller player-counter fields retain
their actual types. Ordinary history totals and greatest per-source amounts retain exact i64
values alongside Fired identity metadata; they do not pack those values into u32 payloads.
Historical source filters still use recorded characteristics and controller.

Actual life changes have magnitude at most u32::MAX because physical life totals remain i32.
Their checked conversion stays a Result assertion in final card files; the optional-answer
rewrite must not turn it into an Option pattern or a unit return in an Option<Fired> callback.
The regression compiles and executes the final rendered Oath of Lim-Dûl matcher.

Legacy and wide profiles are tested separately for shared damage recipes and counter placement.
Target filters requiring unavailable event payloads remain explicit generator limitations in
both profiles. Exact excess-damage history totals additionally require grouping by their
simultaneous event: a recipient aggregate repeated on several source records cannot be summed
as if each were independent. This is a precise unsupported capture/grouping contract, not an
automatic assertion that a new engine feature is required.

Production module preflight and full combined source validation precede any worker-pin change.
The pipeline pin is a separate immutable snapshot; changing this metadata alone does not
promote the queue. Evidence lives under card-lane/pipeline-unlimited-20261103/integration/
composed-foundation-final-proof and wide-history-quantity-proof.
